# 发布更新

1. 修改 `android/app/build.gradle.kts` 中的 `versionName` 和 `versionCode`，内部版本号应大于已发布版本。
2. 更新应用内更新日志并完成测试，用私下保存的正式密钥构建、签名并验证 Release APK。
3. 将正式 APK 上传到本仓库 GitHub Releases。不要上传密钥、密码、本机签名配置或含密钥的私有源码包。
4. Release 使用与应用版本一致的标签，例如 `v1.0.2`。版本说明中加入内部版本标记：

```markdown
<!-- shumanyu-version-code: 3 -->

## 1.0.2 更新内容

1. 修复……
2. 优化……
```

上面的内部版本3仅为下一版示例。应用优先比较此标记的内部版本号；未提供标记时按数字比较版本标签。草稿、预发布版本或未附有效APK的发布不会提示更新。

应用启动时自动检查：成功检查间隔12小时，失败尝试间隔至少15分钟；“稍后”会暂停同一版本提醒24小时。点击提示只打开对应GitHub Release页面，不自动下载安装。

可用 GitHub 网页创建Release，或使用 GitHub CLI：

```sh
gh release create v1.0.2 path/to/shumanyu-1.0.2-release.apk --repo xovikjie/shumanyu --title '书漫屿 1.0.2' --notes-file release-notes.md
```
